# Super Mega Lucky Box

A browser implementation for one to six players on phones, tablets, laptops, and shared tabletop displays. The approved, layered imagegen artwork is the initial commit on `main`. PR1 adds the first playable game for review.

## Play locally

Requires Node 24.18.1 or newer.

```sh
npm ci
npm run dev
```

Open http://localhost:5197/. Create a solo game, invite friends on their own screens, or create a shared tabletop. The server prints LAN addresses for other devices. Firebase anonymous authentication and Firestore use the provisioned `supermega-anicolao` project; no local database is involved.

- `/`: create a table or join by code.
- `/table/CODE`: personal-screen game; seats belonging to your browser are interactive.
- `/tabletop/CODE`: shared table with visible player areas and per-seat rotation on large displays; smaller screens switch between seats.
- `/gallery/`: approved component collection and its original interaction fixture.
- `/gallery/tabletop/`: original tabletop artwork study.
- `/review/`: viewer generated by the shared e2e library, awaiting post-playtest stories.

A shared-table creation seats the requested local players under the table browser's anonymous account. A friends table gives each browser its own seat. Friends tables can also use the tabletop presentation, with each participant making their own choices on their device. Share the full invitation link or QR code to stay on the same build and Firebase scope.

## Game

Choose three of five starting cards. Everyone plays simultaneously over four rounds of nine draws. Tapping an open square automatically spends the fewest lightning tokens needed to reach its number, with 9↔1 wrapping. Undo refunds that cost. Completed rows and columns create pending bonuses; collect tokens/stars directly, or choose a target for fixed-number and wild bonuses. Chains can resolve in either order. Choose Ready after your draw and bonuses. When everyone is ready, the table creator’s browser automatically reveals the next number after a visible three-second countdown. The creator can pause draws for review; undoing Ready cancels the countdown. The first draw and round scoring also advance automatically. A large illustrated countdown precedes the draw, and the card lifts and flips from the deck. Reduced motion skips the bounce and card flight. Ready and Undo stay together below your cards.

Completed cards score 15, 12, 10, and 8 by round. The game implements per-round 1/4/9 star scoring, unfinished-card points, multiplayer moon bonuses/penalties, solo moon scoring, and moon tiebreaks. Between rounds 1–3, keep one of three new cards. Used cards and rejected offers recycle when the deck runs out.

The playable catalog contains 60 layouts, including blank reward positions, with numeric component facts transcribed from BrettspielWelt's published implementation and its reward atlas. See [deck-source.json](src/game/deck-source.json) for provenance and the data checksum. No third-party artwork, sound, or implementation code was copied. The gallery's original six art fixtures remain separate from game data.

Play stays within the viewport. Readable cards use explicit pages when needed; scores, help, and history open in separate paged views under More. Smaller screens use More → Player areas to switch seats.

Ordinary choices apply immediately. Undo restores your own previous choice, including marks, pending/applied bonuses, lightning, moons, stars, and Ready. A new number or new-card deal closes the previous undo window because it reveals new information. The history itself remains append-only.

Gentle synthesized plucks accompany local choices, with separate cues for marks, bonuses, Ready, reveals, scoring, and undo. Sound starts after user interaction; mute is persistent. Remote events and reloads do not replay sound.

## Firebase

[ARCHITECTURE.md](ARCHITECTURE.md) describes the event protocol, transaction/retry behavior, ownership, and trust boundary. Anonymous Auth is configured in `firebase.json`; Firestore rules prohibit event edits/deletion and cross-seat command writes. `src/firebase-config.json` contains the public web-app configuration.

```sh
npx firebase-tools@15.35.0 deploy --only auth,firestore:rules --project supermega-anicolao
```

For isolated local development, start the Firebase emulators (requires Java), then opt the client into them:

```sh
npm run emulators
VITE_USE_FIREBASE_EMULATORS=true npm run dev
```

Dedicated ports are 9297 (Auth) and 8197 (Firestore); phones use the dev server's hostname for both. `VITE_EMULATOR_HOST` overrides that host. `VITE_PREVIEW_ID` isolates preview room histories.

## Checks and playtest boundary

```sh
npm run check
npm test
npm run build
npm run preview
```

`npm test` runs engine unit tests, including complete four-round games for every player count. CI performs source checks, unit tests, and a production build. PR1 intentionally has **no new game e2e tests or screenshot baselines**. After the first playtest, production-UI stories and reviewed screenshots will use the evolving shared [`@anicolao/e2e`](https://github.com/anicolao/e2e) library. [The integration plan](e2e/README.md) records that boundary.

The viewer is implemented in the shared library and consumed via its pinned Git dependency. The application only calls `writeViewer` during dev/build. An empty viewer explicitly says the game awaits playtest; it does not claim screenshot verification. The existing `npm run review:gallery` script is an older artwork diagnostic, not game validation.

## Artwork and license

The same renderers and generated layers serve the gallery, game, and contextual inspector. Original generated PNGs live in `art/source/`; optimized runtime art lives in `public/assets/generated/`. Exact prompts and references are in `art/generation-manifest.json`; `npm run art:prepare` rebuilds delivery assets.

[ART_DIRECTION.md](ART_DIRECTION.md), [UX_DESIGN_PRINCIPLES.md](UX_DESIGN_PRINCIPLES.md), and [VISUAL_DESIGN.md](VISUAL_DESIGN.md) record the approved construction and interaction guidance. Art approval was given before PR1; real-device playtesting remains the next review step.
